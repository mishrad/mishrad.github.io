1. Put the files on GitHub

GitHub builds the site for you. You do not need anything installed.

  1. On GitHub, create a new public repository named exactly mishrad.github.io. The name has to match this pattern or Pages will not serve it at the root. If you already have a repo called webpage, rename it in Settings rather than making a new one.
  2. Unzip the bundle. Upload the contents of the folder, not the folder itself. When you are done, index.html and _config.yml should sit at the top level of the repo, not inside a subfolder.
  3. Go to Settings, then Pages. Source: "Deploy from a branch". Branch: main. Folder: / (root). Save.
  4. Wait about a minute. The site is live at https://mishrad.github.io.
The repo must be public. On a free GitHub account, Pages only serves public repositories. Making it private later unpublishes the site automatically. Anything you commit is readable by anyone, including files Jekyll does not turn into pages.

Confirm the site works at the github.io address before you touch DNS. Debugging a build error and a DNS propagation delay at the same time is miserable.

2. Point your domain at it

Right now mishradibya.com resolves to your TMD hosting account and serves WordPress. This moves the domain to GitHub. Afterwards mishradibya.com serves the new site and mishrad.github.io redirects to it, so both addresses keep working and there is one canonical URL.

Back up WordPress first. Download a copy from TMD before you change anything. Once DNS moves you cannot browse the old site to retrieve something you forgot.

In your TMD DNS panel

Delete the existing A record for @ and the existing CNAME or A record for www. Then add these five records.

TypeHostValue
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwwwmishrad.github.io.

The trailing dot on the CNAME value matters in some panels and is ignored in others. Include it. Leave your MX records alone, they route email and have nothing to do with the website.

In the repo

The bundle already contains a CNAME file holding mishradibya.com, so GitHub picks up the domain on its own. Check Settings, then Pages, and confirm the custom domain field reads mishradibya.com and the DNS check passes. Then tick "Enforce HTTPS".

DNS usually propagates within an hour. The certificate can take a few hours after that. If "Enforce HTTPS" is greyed out, wait and come back.

To make www.mishradibya.com canonical instead, put that in the CNAME file and in the Pages settings. Everything else stays the same.

Once the new site is live and you are happy with it, cancel the TMD hosting plan. Keep the domain registration.

3. Before you call it done

  • Replace assets/images/profile.jpg with your photo. Square crop, same filename, same extension. .jpg and .jpeg are different files and this has broken the site once already.
  • Put your CV at assets/files/cv.pdf. The nav and footer link to it.
  • Fill in the real DOI links for the two 2025 publications on the research page. They are # placeholders now.
  • Replace or delete the other # links. A "Draft" link that 404s is worse than no link.
  • Paste your Google Scholar URL into scholar in _config.yml. Leaving it empty hides the link, which is fine.
  • Expand the two entries on the projects page.
  • Decide whether Cornerstone Research stays in the affiliation block on index.html and in the footer disclaimer.
  • Delete the sample post in _posts/.

4. Add a journal entry

Create a file in _posts/ named YYYY-MM-DD-short-slug.md. The date in the filename controls the ordering and the URL, so it has to be right.

---
title: "What the probe was actually reading"
date: 2026-08-14
summary: "One sentence shown under the title on the journal index."
---

Your text here. Plain Markdown, blank line between paragraphs.

## A subheading if you want one

Links look like [this](https://example.com).

The post appears on /journal/ automatically. There is no index to update. To draft without publishing, give it a future date and it stays hidden until then.

5. Add a paper

Open research.md. Copy one of the existing blocks and edit it. The four sections are Publications, Working papers, Works in progress, and Other writing. Move a block between sections as the work moves along.

<div class="paper">
  <p class="paper-title">Title of the paper</p>
  <p class="paper-meta">With Coauthor Name. Journal, 2026.</p>
  <p class="paper-abstract">Two or three sentences.</p>
  <p class="paper-links"><a href="/assets/files/paper.pdf">PDF</a></p>
</div>

Any of the four lines can be deleted if it does not apply. Works in progress usually have a title and coauthors only. To attach a PDF, upload it to assets/files/ and link it as /assets/files/whatever.pdf.

6. Add a project

Open projects.md. Same block structure as a paper, minus the meta line.

<div class="paper">
  <p class="paper-title">Project name</p>
  <p class="paper-abstract">What it does and what you learned.</p>
  <p class="paper-links"><a href="https://github.com/mishrad/repo">Code</a></p>
</div>

To add a second section alongside Hardware, copy the whole <section class="section"> block and change its <h2>.

7. Add a page

Create a file at the top level, for example teaching.md.

---
layout: page
title: Teaching
permalink: /teaching/
---

Content in Markdown.

Then add a link in _includes/nav.html, copying the line that points at Research.

8. Small edits

Update your CV. Overwrite assets/files/cv.pdf. The links already point there.

Change your affiliation. The block under your name is in index.html, near the top. The footer disclaimer is in _includes/footer.html.

Change research interests. Bottom of index.html.

Change a color. Every color is a variable at the top of assets/css/style.css, in the :root block for light mode and :root[data-theme="dark"] for dark. Change the hex once and it updates everywhere.

9. Keeping files private

The exclude: list in _config.yml only stops Jekyll from turning a file into a page. It does not hide it. In a public repo, a committed file is readable whether or not it renders.

So do not commit anything you would mind being read. This guide, README.md, and MAINTENANCE.md all live outside the repo folder. The bundle ships a .gitignore listing them as a second line of defense if you ever work locally with git.

Deleting is not enough. A file that was committed once stays in the git history and is reachable by anyone who knows to look. Undoing that means rewriting history with git filter-repo, or deleting and recreating the repo.

10. When something breaks

The site 404s at the root. The repo has to be named exactly mishrad.github.io.

A page does not appear. Check the Actions tab for a red X. The usual cause is a typo in the front matter: a missing closing ---, or an unquoted title containing a colon.

The photo is broken. The filename in the HTML has to match the file exactly, extension included.

A post is in the wrong order. Posts sort by the date in the filename, not the date in the front matter. Rename the file.

The custom domain stopped working. Check that the CNAME file still exists in the repo. Some workflows delete it. It should contain one line: mishradibya.com.

Changes are not showing up. Give it a minute, then hard refresh. Pages caches aggressively.
